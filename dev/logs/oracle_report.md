## Divergences that look like bugs, vs. deliberate improvements

### Deliberate improvements (documented in CONTRACTS.md amendments)

- **Every building has an entrance (A6.1).** Old only reaches a door through `has_porte_cochere`; new's `catalogue.entrance_for` picks a porte cochère or a porte piétonne unconditionally. Bucket 3 shows `old_has_porte_cochere=False` alongside a real `new_entrance_kind` for every RESIDENTIAL/SHOP/CAFE/OFFICE row — expected, not a bug.
- **Entresol is programme-first, not remainder (A2.2).** Old's entresol is a probabilistic roll inside whatever the gabarit budget leaves over; new decides it from ground-programme + class before the budget is filled. Divergence in `has_entresol`/`has_mezzanine` across seeds is exactly the effect A2.2 describes, not new disagreeing with old about the same question.
- **Attic is reachable (A2.1).** Old has no attic role at all (its comble is roof, not a storey); new emits one wherever the comble is deep enough. `new_has_attic` being true where old has nothing to compare against is the fix landing, not a regression.
- **Class mapping is lossy by construction.** Old has three style presets (MODEST/RESIDENTIAL/BOULEVARD); new has four classes. ORDINARY and COMFORTABLE both drive the old system through RESIDENTIAL, so old-side distributions for those two classes at the same width/year are close to identical by construction — read the new/old comparison for those rows as 'is new still in a plausible neighbourhood', not 'do the two classes remain distinguishable in old's output'.

### Findings that look like genuine bugs in the NEW system

- None found in the regulatory bucket: every row matched.

- 23 of 320 proportion rows fell outside the stated tolerance, but they are not scattered noise — they resolve into two named, one-directional patterns, both traceable to a *specific* constant rather than to a general disagreement:
  - **`built_height_m`**: 7 outliers, all **new < old range**, concentrated in class(es) modest.
  - **`total_height_m`**: 16 outliers, all **new > old range**, concentrated in class(es) comfortable, grand, modest, ordinary.

  **`built_height_m`, new < old, MODEST-concentrated.** Traces to `structure._FACADE_AMBITION[MODEST] = 0.74` (`structure.py`) — an explicitly INFERRED placeholder (A1.3-style: only the *ordering* MODEST < ORDINARY < COMFORTABLE < GRAND is contractual, the figures are provisional). Old's modest buildings land close to their own legal ceiling because its floor-stacking picks per-floor heights from ranges that happen to sum near the gabarit regardless of an explicit ambition dial. **Not a bug** — it is a placeholder constant behaving exactly as documented — but it is the first place to look if MODEST buildings read as noticeably squatter than the reference corpus in the S11 visual check.

  **`total_height_m`, new > old, growing with street width and era, present across every class including MODEST.** Traces to `structure._COMBLE_FILL = 0.99` (`structure.py`), which is deliberately class-invariant (A2.3: comble fill is floor space, not show, so every class takes nearly all the legal roof) and bounded only by parcel depth, never by how many servant-room storeys the building actually holds. Old bounds the built comble instead by `profile.roof.comble_storeys * mansard.typ` — a fixed few metres regardless of how tall the decree would allow, which is its own uncalibrated placeholder in the other direction. **Worth a second look, not a clear bug**: the new system is doing exactly what A2.3 says it should, but a MODEST building on a wide boulevard now gets a roof nearly as tall as the legal maximum purely because of street width, independent of class — which edges toward the brief's own warning that conflating the legal ceiling with what got built 'makes every building a maximal building, which is wrong and looks it.' That warning was explicitly answered for the FACADE line (`_FACADE_AMBITION` varies by class); this data suggests the COMBLE line may want the same treatment rather than one INFERRED constant near 1.0 for everyone.
